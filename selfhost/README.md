# Ритм — self-hosted версия

Отдельная серверная версия прототипа. Текущий сайт на `chatgpt.site` от этой папки не зависит и продолжает работать как раньше.

Схема боевой установки, ограничения общего сервера и порядок деплоя —
в [ARCHITECTURE.md](ARCHITECTURE.md).

## Что уже подготовлено

- регистрация и вход по email/паролю;
- уникальные ники;
- опциональный вход через Google;
- PostgreSQL и автоматические миграции;
- дневные калории, вес и серия, привязанные к аккаунту;
- поиск пользователей, заявки, принятие и удаление друзей;
- лента достижений друзей;
- настройки приватности (точный вес и калории в ленту не отправляются);
- Docker Compose с автоматическим HTTPS через Caddy;
- healthcheck и скрипт резервной копии;
- установка на домашний экран (PWA): манифест, иконки, офлайн-оболочка;
- приём данных Apple Health по личному ключу.

## Что купить и настроить

Нужен только домен с доступом к DNS. Дополнительный хостинг, SSL-сертификат и почту покупать не требуется.

После покупки создать DNS-записи:

```text
Type: A   Name: @     Value: IP сервера   TTL: Auto
Type: A   Name: www   Value: IP сервера   TTL: Auto
```

Запись `www` обязательна: `Caddyfile` держит для неё редирект на канонический адрес,
и без A-записи Caddy не сможет выпустить для `www` сертификат.

## Локальная разработка

```bash
cp .env.example .env
npm install
npm run db:migrate
npm run dev
```

Для этого PostgreSQL должен быть доступен по `DATABASE_URL`.

## Развёртывание

1. Скопировать папку на сервер.
2. Создать `.env` из `.env.example` и заменить все значения `replace-with-*`.
3. В `APP_DOMAIN` и `BETTER_AUTH_URL` указать купленный домен.
4. Запустить `docker compose up -d --build`.
5. Проверить `https://ДОМЕН/api/health`.

Caddy сам получает и обновляет бесплатный TLS-сертификат. В compose наружу открыты только TCP 80 и TCP 443; PostgreSQL наружу не публикуется.

## Google OAuth

В Google Cloud Console создать OAuth client типа Web application и добавить callback:

```text
https://ДОМЕН/api/auth/callback/google
```

Затем заполнить `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, поставить `NEXT_PUBLIC_GOOGLE_AUTH_ENABLED=true` и пересобрать приложение.

Важно: любые переменные `NEXT_PUBLIC_*` попадают в браузерный бандл на этапе сборки,
а `.env` исключён из контекста Docker. Они передаются build-аргументами из `compose.yaml`,
поэтому после их изменения нужен именно `docker compose up -d --build`, а не перезапуск.

## Установка на телефон

Приложение — PWA: с домашнего экрана оно открывается без адресной строки Safari,
на весь экран и запускается даже без сети (оболочка кэшируется service worker'ом,
данные аккаунта — никогда).

На iPhone: открыть сайт в Safari → «Поделиться» → «На экран „Домой“».
Подсказка об этом сама появляется в приложении и скрывается по крестику.

За внешний вид отвечают `src/app/manifest.ts`, `src/app/layout.tsx` и `public/sw.js`.
Иконки лежат в `public/` (`icon-192.png`, `icon-512.png`, `icon-maskable-512.png`,
`apple-touch-icon.png`) и собраны из `public/icon.svg`.

При изменении `public/sw.js` нужно поднять номер в константе `CACHE`, иначе
у установленных телефонов останется старая оболочка.

## Apple Health

Сайт не может читать HealthKit — iOS не даёт браузеру такого API. Данные присылает
сам телефон через бесплатное приложение «Быстрые команды» (Shortcuts):

```text
POST https://ДОМЕН/api/health-sync
Authorization: Bearer ЛИЧНЫЙ_КЛЮЧ
Content-Type: application/json

{"date":"2026-08-30","activeCalories":512,"steps":8431,"weightKg":61.4}
```

Обязательно только поле `date`; из метрик достаточно любой одной.
Личный ключ пользователь берёт в приложении: «Профиль» → «Apple Health», там же
пошаговая инструкция по сборке команды и кнопка перевыпуска ключа.
Ключ передаётся только заголовком `Authorization`, чтобы не оседать в логах.

Даты команда считает по часовому поясу телефона — это важно, если пользователь
живёт не в том же поясе, что сервер.

Обмен с будущим нативным приложением для iPhone уже заложен: если страница открыта
в `WKWebView` с мостом `window.webkit.messageHandlers.ritmHealth`, в карточке
появляется кнопка ручной синхронизации.

## Резервная копия

Из каталога проекта на сервере:

```bash
set -a; . ./.env; set +a
sh scripts/backup.sh
```

Скрипт хранит 14 дней в `/var/backups/ritm`. Перед реальным запуском следует настроить ежедневный запуск и копирование бэкапа за пределы VPS.

## Перед запуском на предоставленном VPS

- обновить ОС выбранного сервера в отдельное согласованное окно;
- сменить опубликованный в переписке пароль root;
- создать отдельного пользователя с sudo и входом по SSH-ключу;
- включить firewall и оставить только SSH, TCP 80 и TCP 443;
- проверить, что порты не заняты существующими сервисами.
